Does the model you downloaded know when to say "I don't know"?

Independent scorecards for the open models people actually run: the specific file, quantization and server settings, not the lab's full-precision API. Each card measures what a model knows, whether it admits what it doesn't, and whether it refuses too much. Every number links to a receipt.

What a card measures

The core test asks 240 short factual questions built from Wikidata: 40 easy, 100 hard but real, and 100 about things that do not exist (a novel, a university, a person invented from real patterns). A model that knows when to stop should answer the real ones and decline the invented ones.

Knows

How many hard real questions it answers correctly.

Admits it doesn't know

How many invented questions it declines instead of making up an answer.

Refuses too much

How many real questions it declines. A model that refuses everything is not honest, just useless.

Each rate comes with its 95% interval and sample size. A card describes one file at one setting; it is not a rating of the model family.

Latest finding: five post-trained variants say "I don't know" less; two trained with reinforcement learning do not

Five of the seven post-trained variants of open models measured so far declined fewer invented questions than the model they were built from, and none answered more real ones correctly. The two exceptions were both trained with reinforcement learning: a small agent adapter for Qwen3.8-27B, and DaisyRose-27B, a full RL fine-tune of the same model. Both left refusal exactly where it was. Each pair ran on the same build in the same sitting, and each base was replayed that day byte for byte.

Sage's drop held at matched precision and under its own sampling. Full caveats and receipts: the fact sheet. As an agent with thinking off, the pi adapter also said "this task cannot be done" on 13 of 21 impossible tasks where its base said it on 4, with no false alarms on 9 solvable ones (receipt). With thinking on at the base's default effort, both said it on all 7 of a first set of impossible tasks (receipt). With DaisyRose, two RL models of very different size now agree.

Also new: looped models

Looped models run some of their layers more than once per token. Turning one model's loop count from 2 to 3 made it decline 14 more invented questions with answers no longer than before, but it knew fewer facts; neither looped model we measured knows more than a comparable ordinary model.

Why these numbers can be checked

  • The actual file. Every card names the file and its sha256, the build, the flags and the sampling. A label like "Q4_K_M" is not a spec; the hash is.
  • Written down before the run. Each comparison is preregistered, predictions included, and committed before the first answer.
  • Replayed. Base models are rerun alongside each variant and must match their stored answers byte for byte.
  • No lab grades its own homework here. Nothing is sponsored; models are run on hardware I own.
  • Corrections are public. When a number turns out wrong, it is struck, not deleted, and the log below says why.
